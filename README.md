# PetriFire

PetriFire is an interactive Petri net editor and simulator developed as a
university project.

The application allows users to create Petri nets through a graphical editor,
publish them, subscribe to networks created by other users and simulate their
execution through transactions.

When a transition can be fired, the user receives a notification. By selecting
the notification, the user can execute the transition and observe the tokens
moving from the input places to the output places according to the Petri net
rules.

## Petri Net Visualization

Graphviz is used to calculate the layout of each Petri net.

The DOT description is processed through PlantUML and Graphviz-based layout tools to generate a
graphical representation of the net: graphviz calculates the positions of the nodes and edges and 
generates a static image, that is used as a preview of published nets (for example, in the feed).

The resulting coordinates are then extracted and converted into JavaFX
positions. This allows the application to create an interactive panel while
preserving the same layout generated by Graphviz.

The editor does not use free drag-and-drop positioning. Instead, it guides the
user towards creating a structurally valid Petri net.

A contextual menu is available for each element and only provides valid
actions. For example:

- a place can be connected to a transition;
- a transition can be connected to a place;
- invalid connections between two places or two transitions are prevented.

The editor also displays the elements that are not yet correctly connected,
including orphan places and transitions without an output place. This helps
the user understand which parts of the network are still missing before it can
be published.

While the network is incomplete, it can only be saved as a draft and viewed
from the `My Drafts` section. Once all the required connections have been
created and the network is valid, it can be published and made available to
other users.

## Technologies

- Java – application logic
- JavaFX – graphical user interface and interactive visualization
- FXML – layout definitions
- CSS – interface styling
- PlantUML – textual description and rendering of Petri net diagrams
- Graphviz – automatic graph layout calculation

## Setup and Run

### Requirements

* **Java 21 or later**
* **JavaFX SDK 21 or later**
* **IntelliJ IDEA** (recommended)
* SQLite JDBC driver
* PlantUML

### 1. Java

Install a JDK version 21 or later and configure it as the **Project SDK** in IntelliJ IDEA.

### 2. JavaFX

Download the JavaFX SDK and extract it locally.

In IntelliJ IDEA:

1. Open **File → Project Structure → Modules**
2. Select the project module
3. Add all the JavaFX libraries from the `lib` directory of the downloaded JavaFX SDK

### 3. External libraries

The project requires the following additional libraries:

* **SQLite JDBC** — used to access the SQLite database
* **PlantUML** — used to generate/render Petri net diagrams

These can be added through:

**File → Project Structure → Libraries → + → From Maven**

Alternatively, the corresponding `.jar` files can be added manually.

Make sure that the libraries are assigned to the project module in:

**File → Project Structure → Modules → Dependencies**

### 4. Run configuration

Create or edit the application's Run Configuration in:

**Run → Edit Configurations...**

Set the **JRE/SDK** to the Java installation used by the project.

Select "Add VM options," then in **VM options**, specify the path to the `lib` directory of the JavaFX SDK:

```text
--module-path /path/to/javafx-sdk-21.x.x/lib --add-modules javafx.controls,javafx.fxml
```

For example:

```text
--module-path /Users/username/Desktop/javafx-sdk-21.0.7/lib --add-modules javafx.controls,javafx.fxml
```

Set the **Working directory** to the root directory of the project.

This is important because the application accesses the SQLite database using a relative path such as:

```text
src/resources/app.db
```

ensure the "src" folder is marked as "source folder"

### 5. Run

Once the SDKs, libraries, module dependencies and Run Configuration are correctly configured, run the application from IntelliJ IDEA using the project's main class.
